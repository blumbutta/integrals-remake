# Integrals: Remake — сервер

Node.js 24+, без сторонних пакетов. Экономика находится в `../shared/economy.mjs`, испытания — в `../shared/events.mjs`; браузер использует их для локальной игры, сервер — для облачных профилей. Клиент не передаёт баланс, начисления или результат престижа: сервер вычисляет их самостоятельно. Время в идентификаторе действия ограничивает срок повтора и не используется для начислений.

## Локальный запуск

```sh
node server/dev.mjs
```

Игра: `http://127.0.0.1:4180/` или `/integrals-remake/`. Тестовая база создаётся в `.data/integrals-dev.sqlite` внутри каталога игры. Можно задать абсолютный путь через `INTEGRALS_DB_PATH`. Статический сервер не отдаёт содержимое `server/`, скрытые файлы или файлы вне каталога игры.

```sh
node --test server/achievements.test.mjs server/economy.test.mjs server/events.test.mjs server/router.test.mjs
```

## Подключение к общему серверу

```js
import { createIntegralsHandler } from './integrals/router.mjs';
const integrals = createIntegralsHandler({
  dbPath: process.env.INTEGRALS_DB_PATH,
  originAllowed,
});
// В начале обработчика HTTP, до существующих ответов:
if (integrals.handle(request, response)) return;
// При завершении сервера:
integrals.close();
```

Скопировать весь каталог `shared/`, сохранив относительные импорты `../shared/economy.mjs`, `../shared/events.mjs` и `../shared/profile.mjs`, либо скорректировать их при переносе. `handle` синхронно возвращает `boolean`, чтение тела и обработка ошибок происходят внутри. Все остальные маршруты остаются существующим играм. База открывается один раз на экземпляр обработчика.

В production требуется абсолютный `INTEGRALS_DB_PATH` на подключённом постоянном диске, например `/var/data/integrals.sqlite`. Каталог с базой должен переживать перезапуск и развёртывание. `:memory:` запрещён в production. Без настройки или при ошибке открытия только `/integrals-api/*` отвечает `503 storage_unavailable`; остальные игры продолжают работать. База использует WAL, FULL synchronous, транзакции BEGIN IMMEDIATE. Для этого варианта нужен один сервер с локальным постоянным диском; несколько отдельных серверов с разными дисками не образуют общий рейтинг.

Резервировать SQLite нужно согласованно: через SQLite backup API либо после остановки обработчика и checkpoint. Не копировать один основной файл из работающей WAL-базы, игнорируя `-wal`. Файлы базы, WAL и резервных копий нельзя публиковать с фронтендом.

При открытии старой базы сервер в транзакции добавляет отсутствующие `emoji`, `nickname_key` и `display_nickname`, затем создаёт уникальный индекс нормализованных имён. При старых дубликатах первый профиль сохраняет имя, следующие получают устойчивый суффикс в отображаемом имени; исходное имя остаётся в БД до ручного переименования. Публичные ID, ключи доступа, состояния и квитанции сохраняются. Миграция повторяемая: уже назначенные имена и эмодзи не меняются.

## API

Все пути имеют префикс `/integrals-api`. JSON-тело до 2 КиБ. Секретный код передаётся только в `Authorization: Bearer ir_…`. В URL код не передаётся.

| Метод | Путь | Тело / результат |
|---|---|---|
| GET | `/health` | `{ok:true, game, storage, rankingPeriods:['all'], profileNames:'unique-required', economyVersion:2}` |
| POST | `/players` | `{nickname,emoji?}` → `{token,player}`; единственная выдача нового кода |
| GET | `/state` | `{player}`; также heartbeat, рекомендуемый интервал 10–15 секунд |
| POST | `/action` | `{id,type,amount?,itemId?,answers?}` → `{player}` |
| PATCH | `/profile` | `{nickname?,listed?,emoji?}` → `{player}` |
| GET | `/leaderboard?period=all` | `{period:'all',entries,updatedAt}`; верхние 100 |

Действия: `click` (1–24), `buy` (`itemId` генератора, `amount` — целое 1–100), `upgrade` (`itemId` улучшения), `prestige`, `golden`, `event_start`, `event_answer`.

`id` — `${timestamp}-${crypto.randomUUID()}`. `timestamp` — целое epoch ms с поправкой по `player.serverTime`. Допустим возраст не более 15 минут и опережение серверных часов не более 60 секунд. Повтор с тем же идентификатором в этом окне не начисляется повторно и возвращает актуальный профиль. Изменение содержимого при повторном идентификаторе возвращает `409 action_conflict`. Старый идентификатор всегда получает `409 action_expired` до изменения профиля, даже если запись о нём уже удалена. Слишком далёкое будущее: `409 action_from_future`.

Квитанции действий переживают перезапуск и очищаются раз в 60 секунд, максимум 5000 истёкших записей за проход, по индексу времени. При обычной нагрузке хранится примерно 15–16 минут действий вместо всей истории. Клиент должен повторять потерянный запрос с прежним `id`, а не новым. Непереданные ручные действия после 15 минут отсутствия связи больше не применяются; автоматическое производство рассчитывается независимо и сохраняется по офлайн-правилам.

`player`: `economyVersion`, `id` (публичный случайный UUID), `nickname`, `emoji`, `listed`, `serverTime`, `lastSeen`, `lastSettled`, `balance`, `totalEarned`, `runEarned`, `clicks`, `generators` (массив количеств в порядке `GENERATORS`), `upgrades` (идентификаторы), `achievements` (идентификаторы достижений и личных наград `prestige:n`; сохраняются после престижа), `achievementRecords` (пики количества помощников, исследований и производства), `activeEvent`, `eventCooldowns`, `eventStats`, `lastEventResult`, `prestige`, `prestigeCount`, `golden:{availableUntil,nextAt}`, `offlineEarned`, `stats:{cps,clickPower,multiplier,prestigeGain,baseCps,flatClickPower,clickProductionShare,teamworkBonus,generatorRates}`, `generatorPrices`, `availableUpgrades`.

Эмодзи выбирается из общего `PROFILE_EMOJIS` в `shared/profile.mjs`; `DEFAULT_EMOJI` равен `🧠`. `isProfileEmoji(value)` проверяет точное вхождение в список, `profileEmoji(value)` возвращает разрешённое значение либо default для отображения старых сохранений. API отклоняет неподдерживаемую строку, несколько эмодзи, `null` или другой тип с `400 invalid_emoji`. Отсутствующее поле при создании означает default, а при изменении профиля сохраняет предыдущий выбор.

Рейтинг содержит только `{id,nickname,emoji,totalEarned,balance,prestige,rank}`. Основной счёт — `totalEarned`, весь серверный заработок за всё время; сортировка по убыванию этого поля. При равенстве выше профиль, созданный раньше, затем используется внутренний ID только для стабильной сортировки. `rank` начинается с 1. `balance` — отдельный текущий остаток после покупок и штрафов, `prestige` — накопленные очки престижа; они не меняют порядок. Рейтинг показывает последние сохранённые сервером значения и обновляется при heartbeat/действии игрока. Новый профиль создаётся только после ввода уникального имени; по умолчанию он участвует в рейтинге, участие можно выключить. `period=week` честно возвращает `400 unsupported_period`. Email не запрашивается и не хранится. Хеши и коды доступа, внутренние ID, ответы испытаний и полное состояние в рейтинг не входят.

Имя обязательно при `POST /players`; при `PATCH /profile` отсутствие имени сохраняет прежнее. `normalizeNickname` применяет NFKC, удаляет крайние и повторные пробелы. Разрешено 2–24 символа без управляющих символов, адресов и ссылок. `nicknameKey` дополнительно нормализует регистр; уникальность проверяется в транзакции и подкреплена индексом SQLite, включая скрытые из рейтинга профили. Занятое имя возвращает `409 nickname_taken`, некорректное — `400 invalid_nickname`. Имя не является средством входа.

Код восстановления содержит 256 случайных бит, в БД находится только SHA-256. Код является полным доступом к профилю; восстановление на другом устройстве — вход с тем же кодом. Утраченное значение из хеша не восстановить. Сервер не печатает коды, тела запросов или данные SQL в логах.

Ошибки: `{error:{code,message}}`. Типовые статусы: 400 — некорректное действие/недоступная покупка; 401 — неверный код; 403 — Origin; 409 — конфликт идентификатора или занятое имя; 429 — лимит; 503 — хранилище.

## Экономика и ограничения

Первый генератор: 15 интегралов, 0,25/с. Цены растут в 1,15 раза. Клики: серверный token bucket 12/с, запас 24, состояние лимита также хранится в SQLite. Производство полное первые 30 секунд после heartbeat, затем 50% ещё не более 12 часов отсутствия. Повторные чтения не позволяют повторно получить уже начисленный офлайн-доход. Для престижа нужно накопить на балансе 999 999 999 999 999 интегралов; очки = `floor(sqrt(runEarned / 1e6))`, каждое даёт +10% производства и силы клика. Престиж сбрасывает текущие покупки и баланс, сохраняя исторический заработок.

Экономика версии 2 сохраняет цены и старые идентификаторы исследований. 86 исследований включают прежние 26, пять усилений ручного клика и по пять новых исследований на каждый ресурс: командная работа при 50 помощниках, множители ×3/×4/×6/×10 при 50/75/100/150 помощниках. Стоимость производственных уровней — базовая цена ресурса ×500/×8 000/×120 000/×30 000 000. Сверхразум по-прежнему стоит 10 000 000 000 000 ∫, его новая базовая скорость — 8 000 000 000 ∫/с.

`clickPower = flatClickPower + cps × clickProductionShare`: доля начинается с 5% и исследованиями повышается до 20%. Престиж применяется один раз к плоской силе и производству; повторного усиления процентной части нет. При трёх кликах в секунду это даёт 15–60% дополнительного производства плюс плоскую силу.

После командного исследования категория из `n` помощников добавляет `0.2 × n / (n + 100)` базового производства всей лаборатории. Базовое производство включает ресурсные исследования и престиж, но не командные бонусы. Вклады категорий складываются; предел каждой категории — 20%. `generatorRates` относит командный доход к усиливающему ресурсу, чтобы ранние помощники показывали свой полный вклад в подсказке.

У новых сохранений `economyVersion:2`. При первом `settle` старого состояния без этой версии незакрытый интервал начисляется по прежним базовым скоростям и старым купленным множителям, затем состояние получает версию 2. Следующие интервалы используют новые ставки. Уже записанные балансы, заработок, покупки и награды не пересчитываются.

Золотой интеграл появляется раз в 90–180 секунд и доступен 15 секунд. Награда вычисляется сервером: большее из 25 кликов и 60 секунд производства; повторное получение невозможно. Клиентские часы и переданная клиентом сумма не влияют на награду. На клиенте это медленно движущийся золотой интеграл, а не карточка; при развитом производстве награда остаётся равна 60 секундам производства даже с максимальным исследованием ручного клика.

Общие ограничения: 900 запросов/минуту и 20 новых профилей/час с одного адреса. На Render адрес берётся из заголовка reverse proxy `X-Forwarded-For`; при другом хостинге нужно гарантировать доверенный proxy или использовать адрес сокета. Ограничение кликов делает результат проверяемым по правилам игры, но само по себе не отличает ручные клики от автоматизации на допустимой скорости.

## Проверки

Тесты покрывают цену и производство, апгрейды, престиж, достижения, окно золотого интеграла, 12-часовой лимит и повторные начисления, токены и приватность рейтинга, сохранение после повторного открытия SQLite, аддитивную миграцию старой БД и эмодзи после перезапуска, различие баланса и счёта рейтинга, параллельные покупки, идемпотентность и истечение квитанций, коллизии идентификаторов, лимиты кликов, недопустимые поля, Origin, независимость маршрутов и недоступное хранилище. Испытания проверяются для всех двенадцати типов: правильные/неверные ответы, разблокировка, таймаут, защита ответов и наград, отсутствие отрицательного баланса и повторного начисления.

## Необязательные испытания

Испытание открывается после покупки соответствующего помощника. По одному типу на девять помощников после Автоклика: школьник — арифметика; студент — производные; преподаватель — неверное равенство; компьютер — двоичный код (90 секунд); профессор — интегралы; ИИ — последовательности; портал — восстановление исходного числа по трём видимым цепочкам операций (75 секунд); машина времени — сортировка шести чисел; Глубокая мысль — логика. В мире также доступны школьная олимпиада, метеоры портала и научное открытие. Все 12 заданий доступны через карту, отдельной вкладки событий нет. Названия, рисунки и события закрытых районов скрыты до покупки соответствующего помощника.

Экспорт `EVENTS`: `{id,generatorId,name,description,rules,kind,durationSec,rewardClicks,cooldownSec}`. `eventAvailable(state,eventId,now)` сообщает возможность запуска. `getPublicEvent(state.activeEvent)` возвращает безопасную публичную проекцию:

```js
{
  id, eventId, kind, name, startedAt, deadline, reward, penalty,
  prompts: [{prompt, options?, circuit?: {steps, output}}],
  data: {digits?, memorizeUntil?, numbers?}
}
```

`event_start`: `itemId` — идентификатор из `EVENTS`. `event_answer`: `itemId` — **UUID текущего экземпляра** `activeEvent.id`; `answers` — три индекса вариантов для `kind:'quiz'` или шесть чисел в правильном порядке для `kind:'sort'`. Новые «Обратные сигналы» — `quiz`: все цепочки `circuit` остаются видимыми до конца. Поддержка `kind:'reverse'` и ответа `['4321']` оставлена только для уже начатых старых испытаний. Время целиком — от старта до `deadline`.

`eventStakes(stats, definition)` возвращает `{reward, penalty}`. Обе суммы равны `max(rewardClicks × clickPower, cps × 30)` и фиксируются в момент запуска. В развитой лаборатории с максимальной долей клика новые задания стоят примерно от 30 до 144 секунд производства: простые сохраняют нижний порог, сложные растут вместе с ручной силой. Уже начатые испытания из старых сохранений сохраняют свои прежние ставки. При ошибке или истечении времени снимается не больше текущего баланса. Исторический заработок и рейтинг не уменьшаются; повторный ответ не повторяет выплату/штраф. Правильные ответы находятся в приватном `_answers` в серверной SQLite-state и не передаются в API. Переданный клиентом размер выплаты отвергается как неизвестное поле.

Одновременно активно одно испытание. Пауза между запусками одного типа — 5 минут от старта. `eventStats:{wins,losses}` сохраняет результаты, `eventCooldowns:{[eventId]:epochMs}` — время следующего старта. `lastEventResult:{id,eventId,outcome:'win'|'loss'|'timeout',reward,penalty,at}` сообщает итог. Престиж доступен после завершения активного испытания. Без явного запуска испытания штрафов нет; основная игра продолжает работать во время решения.

## Достижения и оформление

`shared/achievements.mjs` содержит 120 обычных достижений и 20 открываемых оформлений. Исходные 12 идентификаторов сохранены. Награды за клики, помощников, производство, исследования, испытания и перерождения меняют только оформление, не добавляя валюту или множители. Пики `achievementRecords` фиксируются до сброса прогресса и передаются в приватном ответе профиля для корректного отображения прогресса на другом устройстве.

`collectAchievements(state,stats)` возвращает новые идентификаторы, обновляя список и пики. `cosmeticUnlocked(state,id)` проверяет требования выбранного оформления. `prestigeAppearance(prestigeCount)` даёт детерминированный облик по номеру **перерождения**, независимо от числа заработанных очков престижа: первые восемь имеют отдельные названия и направления, следующие используют процедурный цвет и параметры узора.

Каждый фактический `applyAction({type:'prestige'})` добавляет один значок `prestige:n`. Старые сохранения не разворачивают неизвестную историю в огромные массивы: `getPrestigeHonors(count,{offset,limit})` строит отображаемые награды лениво, максимум 100 за вызов. Миграция достижений не меняет баланс; переход экономики на версию 2 описан выше.

`migrateState(state)` дополняет старые массивы из 10 генераторов и их пиков нулевым одиннадцатым слотом Сверхразума, сохраняя прочие поля и возвращая тот же объект. `settle` вызывает миграцию автоматически. Ранее полученные `all` и `upgrades-24` сохраняются; «Единая теория» требует все 11 видов, исследования имеют отдельные достижения на 26, 40, 60 и 86 покупок за цикл. Все старые идентификаторы исследований, достижений и оформлений действительны.
